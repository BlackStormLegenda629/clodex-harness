# Clodex Harness

Clodex Harness — нативное Android-приложение для чата и работы с кодом через выбранного ИИ-провайдера. Работает на телефонах и планшетах, интерфейс на русском. Для запросов к модели нужен собственный ключ провайдера.

- **Чат:** потоковые ответы, выбор модели, поддерживаемый провайдером веб-поиск и MCP-коннекторы.
- **Code:** открытие локальных папок и GitHub-репозиториев, просмотр диффов и применение правок.
- **HTML:** карточка артефакта, изолированный предпросмотр и исходник с подсветкой.
- **Внешний вид:** светлая и тёмная темы, двухпанельная раскладка на планшетах. В **Настройки → Внешний вид** можно переключаться между «Классикой» и «Студией» без переустановки.
- **Обновления:** сборка с настроенным GitHub Releases показывает «Что нового» при запуске. APK скачивается только после нажатия «Установить»; последнее слово за системным установщиком Android.

Изменения и инструкции по выпуску: [CHANGELOG](CHANGELOG.md) · [Сборка и публикация релизов](docs/releases.md) · [Как помочь проекту](CONTRIBUTING.md).

Исходный код — [Apache 2.0](LICENSE). У [сторонних ресурсов](docs/third-party.md) отдельные условия. Для сообщений об ошибках и предложений используйте Issues; не прикладывайте ключи, OAuth JSON и личные данные.

## Сборка и запуск

1. **Шрифты.** Все шрифты лежат в `app/src/main/res/font/` и в рантайме из сети не грузятся. Для интерфейса доступны Inter, Manrope, Noto Sans и системный; для кода — JetBrains Mono, Fira Code, IBM Plex Mono, Source Code Pro и System Mono.
2. **Gradle wrapper.** Уже в комплекте (`gradlew`, `gradle/wrapper/`). Достаточно JDK 17+; Gradle 8.9 скачается сам.
3. `./gradlew assembleDebug` или Run из Android Studio. minSdk 26, compile/targetSdk 35.
4. Тесты: `./gradlew testDebugUnitTest`.

## Как работает ответ модели

- Без ключа провайдера чат показывает ошибку с подсказкой, куда добавить ключ (демо-ответов нет).
- Ответ идёт через `AgentRunner`: модель может вызывать инструменты подключённых MCP-коннекторов (имена `<коннектор>__<инструмент>`). Не больше 8 раундов инструментов, результат инструмента обрезается до 64 КБ, поток провайдера — до 1 МБ. Инструменты без `readOnlyHint: true` выполняются только после «Разрешить» в панели над полем ввода.
- **«Ход рассуждений»** над ответом показывает только факты: явные сводки провайдера (`reasoning_summary`, `reasoning_details[type=reasoning.summary]`) и события агента («Вызываю GitHub · search», «Получен результат…»). Сырой ход мыслей модели (`thinking`, `reasoning_content`) намеренно не показывается и не сохраняется. Если ничего такого не пришло, шаги нейтральные: «Анализирую запрос», «Формирую ответ». Время и шаги сохраняются в сообщении (миграция БД 2→3 без потери чатов).
- Пока ответ генерируется, чат в списке и боковой панели помечен точкой и подписью «В работе · только что»; кнопка отправки превращается в «Остановить» (частичный текст сохраняется). Пустой ответ модели — ошибка, а не «…».
- Настройки → Провайдер → **Anthropic** и введён ключ: стриминговый `POST https://api.anthropic.com/v1/messages` (`x-api-key`, `anthropic-version: 2023-06-01`), выбранная модель, веб-поиск через tool `web_search_20250305`, если включён в меню «+».
- **OpenAI-совместимый** или **Свой провайдер** с URL и ключом: `POST {url}/chat/completions` (формат OpenAI) или `/v1/messages` (формат Anthropic). Кнопка «Проверить» делает `GET {url}/models`.
- **OpenRouter**: укажите `https://openrouter.ai/api/v1` и формат OpenAI в своём провайдере. «Веб-поиск» в меню «+» включает плагин OpenRouter `web` для выбранной модели с тем же ключом; поиск может расходовать дополнительные кредиты. Для встроенных OpenAI и DeepSeek и других OpenAI-совместимых адресов этот переключатель не поддерживается.
- Идентификаторы моделей берутся из каталога (`Sonnet 5.5` → `claude-sonnet-5-5`). После «Проверить и модели» у встроенного провайдера точные ID с сервера добавляются в выбор модели, а названия из каталога, которых сервер не вернул, помечаются «Не найдена у провайдера»; выбранная модель заменяется на настоящую. Точный ID с сервера всегда отправляется как есть.
- Системный промпт = инструкции агента + инструкции и текстовые файлы проекта чата (до ~24 КБ).

## Как работает Code

- «Файлы» в сессии — окно просмотра папки через SAF или ветки GitHub, без редактирования из самого окна. Из списка можно открыть `.html`/`.htm`; у HTML-блоков в ответах есть отдельный предпросмотр без JavaScript и сетевых запросов. Code не запускает команды, сборки или тесты.

- Сессия работает в выбранной рабочей области: **папка на устройстве** (SAF, «Выбрать папку») или **GitHub-репозиторий** `owner/repo`. Перед первым запросом к модели проверяется доступ (список корня папки или ветка по умолчанию репозитория); при ошибке модель не вызывается.
- У агента три инструмента: `workspace_list`, `workspace_read` (текст до 256 КБ), `workspace_write` (полное содержимое, до 512 КБ). Пути только относительные: `..`, абсолютные пути, `\`, `%2F` и управляющие символы отклоняются. Двоичные файлы видны в списке, но не читаются и не перезаписываются.
- `workspace_write` ничего не пишет сразу: правка копится. Режимы: **План** — инструмента записи нет; **Правки** — после ответа появляется карточка «Применить изменения» со списком файлов и диффом; **Авто** — правки применяются сами в конце ответа.
- Применение по-настоящему: в папке файлы пишутся через SAF (если файл изменился после чтения — он не перезаписывается и помечается «не записано»); в GitHub создаётся ветка `claude/<задача>-<id>` от ветки по умолчанию и один коммит (Git Data API: tree → commit → ref, режим `100755` сохраняется, ссылки и подмодули не трогаются). Нужен токен GitHub с правами Contents и Pull requests (Настройки → Подключения).
- «Создать PR» появляется только после успешного коммита в GitHub; номер и ссылка берутся из ответа GitHub. Для папок на устройстве PR нет.
- Таймлайн: «Прочитал/Просмотрел/Подготовил изменение <путь>» по реальным вызовам, «Ход рассуждений» (те же правила, что в чате), коммит/запись, PR, ошибки. Ошибка не попадает в историю сообщений — «Повторить» отправляет тот же разговор. «Остановить» прерывает ответ без записи файлов; прерванная закрытием приложения сессия становится «Прервано».
- Миграция БД 3→4 добавляет события и изменения сессий, старые сессии сохраняются.

## Допущения (в HTML этого нет, решено самостоятельно)

- **Уровень усилий** меняет только `max_tokens` (1024 / 2048 / 4096 / 8192 / 16000). Отдельное поле API не отправляется: для этих моделей не проверял.
- **Шторка** сделана своей, а не `ModalBottomSheet`: у него по публичному API не задать кривую и 340/250 мс (по памяти, не проверял). Свайп вниз, системная «назад», затемнение 200 мс сохранены.
- Поверхность всех шторок полностью непрозрачна; полупрозрачным остаётся только затемнение экрана за шторкой.
- Модели показывают PNG-логотипы семейств, в том числе через сторонние шлюзы. Если семейство и провайдер не распознаны, показывается буквенный знак. PNG: [Lobe Icons](https://github.com/lobehub/lobe-icons) (MIT).
- Отдельный single-file пример строки «Ход рассуждений» и модального окна «Сводка» находится в корне: [`thinking.html`](thinking.html).
- **Шестерёнка** есть и в шапке Чата: так в HTML (в ТЗ перечислены только Проекты, Code, Артефакты).
- «Веб-поиск» в чате и «Доступ агента в интернет» в разрешениях в HTML делили один флаг; здесь это два разных (`web` и `agentWeb`).
- Две дополнительные чата-заготовки («Миграции», «Цвета и размер в HTML») созданы, чтобы чаты проектов из HTML вели в реальные чаты.
- Таймлайн сессии Code строится только из реальных событий (см. «Как работает Code»), а не из шагов прототипа. «Откатить» из HTML убран: отменить можно только до применения («Отклонить»).
- Экран «Изменения» остался экраном (в HTML так), а не шторкой.
- Пока открыта клавиатура, нижние вкладки скрываются.
- Токен GitHub: отдельная строка в Настройки → Подключения (в HTML её нет).
- В настройках разрешений выбирается режим новых сессий Code. Для изменяющего вызова коннектора можно разрешить один вызов или запомнить конкретный инструмент только в этом чате; сохранённые разрешения отзываются там же. Изменение подключения, учётных данных или описания инструмента требует нового согласия. Отзыв не отменяет уже начатый вызов.
- HTML открывается в отдельном просмотрщике с переключением между страницей и исходником. JavaScript и сетевые запросы в WebView отключены.
- Для Android 8–9 скачивание в «Загрузки» запрашивает WRITE_EXTERNAL_STORAGE, на 10+ идёт через MediaStore без разрешений.
- «Удалить все данные» чистит БД, файлы и настройки, потом возвращает встроенные скиллы и каталог коннекторов (все в «Обзоре») и один пустой чат.
- Ключи API лежат в DataStore открытым текстом (приватное хранилище приложения). Для продакшена стоит перенести в Keystore.

## Подключение MCP и работа в фоне

- У ряда коннекторов каталог содержит адрес сервера и запускает браузерный OAuth с PKCE. Для GitHub предусмотрен ввод токена. Gmail использует Google Identity Services вместо формы токена, запрашивает доступ на чтение и становится подключённым только после успешного `list_labels`. Для реального входа требуется Android OAuth-клиент, зарегистрированный на пакет и сертификат APK; его регистрация и вход пока не подтверждены. Figma ограничивает список допустимых клиентов.
- Для Gmail MCP Google требует [участие в Developer Preview](https://developers.google.com/workspace/gmail/api/guides/configure-mcp-server), включённые Gmail API и Gmail MCP API и OAuth-клиент с флажком **Use this client for an AI-powered agent**. Доступ только на чтение не предотвращает передачу результатов инструмента выбранному провайдеру модели: письма и черновики могут попасть в контекст чата.
- Запущенный в чате или Code ответ использует foreground service и может продолжаться после сворачивания и закрытия экрана. Запрос на подтверждение инструмента ждёт пользователя. Принудительная остановка Android, перезагрузка или завершение процесса прерывают ответ; автоматически запросы не отправляются заново.
- Полный вход в личный аккаунт и работа после закрытия на планшете не проверены.

## Память и расписание

- **Память.** В «Данные и приватность» доступна общая память, а в проекте — отдельные заметки проекта. Только включённые заметки добавляются к новым запросам Chat и Code. Удаление заметки не удаляет текст, который уже попал в историю чата или был отправлен провайдеру.
- **Запланированные сообщения.** Для активного чата можно запланировать одно сообщение или повтор каждый час / каждые 24 часа. Расписание сохраняет чат и модель, не запускает инструменты и зависит от сетевых и фоновых ограничений Android. Если отправка уже началась, отмена не может отозвать её у провайдера.

## Настройки программирования

«Настройки → Программирование» объединяет режим новых сессий Code, инструкции, модель и усилия, веб-поиск, скиллы и выбор рабочей области. Это настройки, а не замена основного экрана Code. Модель, усилия, инструкции и поиск общие с Chat и используются в следующих запросах; смена режима по умолчанию или рабочей области не переносит существующие сессии и их правки.

Включённые скиллы с непустым текстом передаются в Chat и Code как инструкции (не более 12 000 символов суммарно). Пустые встроенные карточки не добавляют инструкций. Скиллы не устанавливают исполняемые плагины и не дают агенту возможности запускать команды, сборки или тесты.

## Отложено (интерфейс готов, логики нет)

- **Настраиваемые уведомления.** Переключатели сохраняются, но не управляют уведомлениями. Во время ответа используется служебное уведомление Android; его видимость зависит от настроек системы.
- **Вложения** (камера, фото, файлы, видео) выбираются, показываются чипами и перечисляются в тексте запроса, но содержимое в API не отправляется.
- **Команды в Code.** Агент работает с файлами (список, чтение, запись), но не запускает shell, сборку и тесты: на Android через SAF это невозможно, и агенту это прямо запрещено утверждать.

## Проверка перед сдачей (чек-лист, не пройден)

Не проверено на устройстве: пиксельное совпадение отступов и радиусов, обе темы, все анимации, поворот экрана, пустые списки, неверный адрес GitHub. Логика покрыта unit-тестами (ниже); `assembleDebug testDebugUnitTest` проходит.

- `SkillsViewModelTest`: создание вручную, правка, установка из GitHub (в том числе ветка по умолчанию, дубликат, неверный адрес, сбой сети), встроенный скилл не удаляется, парсер frontmatter и адресов.
