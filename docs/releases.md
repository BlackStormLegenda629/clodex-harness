# Релизы Clodex

Сборка из исходников не требует локального OAuth JSON и ключей провайдеров. Обычная отладочная сборка (`./gradlew assembleDebug`) предназначена для разработки. Для публичных APK нужен отдельный закрытый ключ подписи: не кладите его и пароли в репозиторий. Ключ должен оставаться одним и тем же между публичными выпусками.

1. Увеличьте Android `versionCode` и обновите `versionName` перед выпуском. Текущий выпуск — `versionCode 4`, `versionName "1.0"` (тег `v1.0`); перед следующим APK код нужно поднять снова.
2. Запустите `./gradlew testDebugUnitTest`, соберите и подпишите один APK для публикации.
3. Проверьте подпись через `apksigner verify --print-certs <apk>` и попробуйте обновить предыдущую сборку без удаления приложения.
4. Создайте **GitHub Release** с тегом версии, приложите подписанный APK по соглашению ниже и напишите в описании, что изменилось. Коммит или тег без опубликованного релиза не распространяет APK.

Android не обновит установленное приложение APK с другой подписью. Если старая тестовая сборка и публичный релиз подписаны разными ключами, переход между ними нужно планировать отдельно: удаление приложения может стереть локальные чаты и настройки. Не переиспользуйте тестовый ключ как публичный по умолчанию.

Пример ручной подписи (команды `zipalign` и `apksigner` поставляются с Android SDK Build Tools; пароль вводится по запросу, а не в командной строке):

```sh
./gradlew assembleRelease   # канал уже BlackStormLegenda629/clodex-harness
zipalign -P 16 -f 4 app/build/outputs/apk/release/app-release-unsigned.apk clodex-aligned.apk
apksigner sign --ks "$HOME/clodex-release.jks" --ks-key-alias clodex --out clodex-4.apk clodex-aligned.apk
apksigner verify --print-certs clodex-4.apk
```

Замените `4` на фактический `versionCode`. Храните резервную копию ключа в защищённом месте. Для входа через Gmail зарегистрируйте Android OAuth-клиент под идентификатором пакета и SHA-1 **публичной** подписи отдельно от отладочного клиента.

## Обновление из приложения

- Канал по умолчанию — `BlackStormLegenda629/clodex-harness`. Переопределите его через `-PclodexUpdatesRepo=OWNER/REPO` или отключите пустым значением: `-PclodexUpdatesRepo=`. Токен GitHub и учётные данные не используются.
- Clodex проверяет выпуск при каждом возврате приложения на передний план, после короткой паузы. Неудачная проверка повторяется через 10 и 30 секунд; после успешной — минутная пауза. «Что нового» показывается на главном экране. Проверка вручную: **Настройки → Обновления → Проверить обновления**. Приложение запрашивает `/repos/OWNER/REPO/releases/latest` и не предлагает черновики или предварительные выпуски. Если последний стабильный выпуск не содержит подходящего APK, к более ранним выпускам приложение не переходит.
- Приложите один самостоятельный (не split) APK размером до 200 МиБ с именем **`clodex-<versionCode>.apk`**, например `clodex-42.apk`. Это десятичный Android `versionCode` из `app/build.gradle.kts` без ведущих нулей, не `versionName` и не тег. Повышайте код с каждым выпуском. Тег используйте без `/`, например `v1.2.3`; отметьте выпуск как последний стабильный.
- Описание показывается обычным текстом, без ссылок и HTML. «Позже» закрывает предложение, «Установить» начинает скачивание. Если Android запретил установку из этого источника, откройте предложенные системные настройки, вернитесь и снова нажмите «Установить»: автоматического скачивания или установки нет.
- До передачи системному установщику приложение проверяет имя пакета и точное совпадение текущих сертификатов подписи с установленной копией (истории ротации недостаточно), а также что код APK выше установленного и совпадает с кодом из имени файла. Установку подтверждает пользователь в Android.
